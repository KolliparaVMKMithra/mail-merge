Microsoft Power Automate Setup Guide

This dashboard triggers emails by sending HTTP POST requests to an instant cloud flow inside Microsoft Power Automate. Follow these simple steps to configure your webhook and connect it to your Outlook email account.

1

Create Instant Cloud Flow

Sign in to Power Automate, navigate to "Create", and choose "Instant cloud flow". Choose a name and select "When an HTTP request is received" as the trigger, then click Create.

2

Paste Trigger JSON Schema

In the trigger configuration, click "Use sample payload to generate schema" and paste the JSON schema below. Power Automate will automatically configure the data parameters.

JSON Payload Schema 
{
  "type": "object",
  "properties": {
    "email": { "type": "string" },
    "name": { "type": "string" },
    "companyName": { "type": "string" },
    "subject": { "type": "string" },
    "body": { "type": "string" },
    "attachment": {
      "type": "object",
      "properties": {
        "name": { "type": "string" },
        "contentBytes": { "type": "string" }
      }
    }
  }
}
3

Add Email Sending Action

Click "New step" and add the "Send an email (V2)" action (from Office 365 Outlook or Outlook.com).

  • To: Select email from the dynamic content trigger.
  • Subject: Select subject from the dynamic content trigger.
  • Body: Select body from the dynamic content trigger (set format to HTML if you plan to send HTML-formatted emails).
4

Configure Dynamic Attachment

Click "Show advanced options" at the bottom of the Email Action card.

  • Under Attachments - 1 Name: Click and select attachment / name from the dynamic content trigger.
  • Under Attachments - 1 Content: Go to the "Expression" panel in the dynamic window and enter the following formula to translate our Base64 string back into binary:
    base64ToBinary(triggerBody()?['attachment']?['contentBytes'])
5

Save Flow & Copy URL

Click "Save". Power Automate will now generate a unique HTTP POST URL inside the trigger. Copy this URL, open the `.env` file in your workspace, and paste it into the POWER_AUTOMATE_URL variable.

POWER_AUTOMATE_URL="https://prod-..."

Important: Under the HTTP trigger's advanced settings, ensure "Who can trigger the flow" is set to "Anyone" (not "Any user in my tenant") to allow direct trigger access from FlowMail.

Make sure to restart your Express backend after updating your `.env` file!

To fetch bounced or failed email delivery reports from your Outlook inbox, you can configure another instant cloud flow that queries your inbox and returns the list of messages.

1

Create Bounce Fetcher Flow

Sign in to Power Automate, select "Create", and choose "Instant cloud flow". Set the name to FlowMail Bounce Fetcher, select "When an HTTP request is received" as the trigger, and click Create.

2

Add Outlook Get Emails Action

Click "New step", select the "Office 365 Outlook" (or Outlook.com) connector, and add the action "Get emails (V3)". Set the options as follows:

  • Folder: Inbox
  • Search Query: subject:Undeliverable (this filters the query to fetch only bounce notifications).
  • Top: 100 (maximum number of emails to scan).
3

Add Response Action

Click "New step" and select the "Response" action under Request. Set the properties to return the list of fetched emails back to FlowMail:

  • Status Code: 200
  • Headers: Add key Content-Type and value application/json
  • Body: Click inside the field and select the dynamic content array parameter value from the "Get emails (V3)" step output.
4

Save Flow & Copy Bounce Webhook URL

Click "Save". Power Automate will now generate a unique HTTP POST URL inside the HTTP trigger card. Copy this URL, open the `.env` file in your workspace, and paste it into the POWER_AUTOMATE_BOUNCE_URL variable.

POWER_AUTOMATE_BOUNCE_URL="https://prod-..."

Important: Under the HTTP trigger's advanced settings, ensure "Who can trigger the flow" is set to "Anyone". If set to "Any user in my tenant", Microsoft will reject calls with a 401 Authorization error.

Make sure to restart your Express backend after updating your `.env` file!
